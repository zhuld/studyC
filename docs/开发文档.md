本仓库是《The C Programming Language》第 2 版（中文简体译本）的交互式阅读实现。课程按教材目录顺序组织，阅读区与代码工作台分离，支持在线编译、复制、行号高亮与滚动定位。

### 课程内容

### 阅读与运行

- **课程与代码分离**：切换章节不会覆盖工作台内容；从正文代码块载入代码时工作台自动展开。
- **教材正文可直接运行**：正文里「带 `main` 的完整程序」（当前 38 处）在代码块下方自动获得「载入编辑器 / ▶ 运行」入口，判定规则见 [`code-blocks.js`](../code-blocks.js)。
- **代码块一键复制**：正文的每个代码块右上角都有「复制」按钮，点击即复制整段代码并短暂显示「已复制」（Clipboard API，非安全上下文回退 `execCommand`）。
- **语法高亮**：编辑器高亮层与教材正文的每个代码框共用同一套 C 着色规则——注释、字符串、预处理指令、关键字、类型、数字与函数名分别着色（[`highlight.js`](../highlight.js)）。
- **在线编译**：调用 [Wandbox](https://wandbox.org) 公开 API（CORS 开放，浏览器直连，无需后端）。编译器下拉框由 `list.json` 中 `language === "C"` 的条目填充；C 标准可选（c89 / c99 / c11 …），默认 **C89**——教材描述的是 ANSI C。支持 stdin 标准输入；Wandbox 不可用时退化为内置占位编译器，页面仍可打开。
- **代码编辑器**：行号、C 语法高亮、Tab 缩进（4 空格，Shift+Tab 反缩进）、`Ctrl+Enter` 运行，零 CDN 依赖。
- **独立代码工作台**：可拖动、缩放、关闭，页面加载后默认隐藏（顶部工具条的「打开代码工作台」按钮打开）；关闭后可从顶部重新打开，拖动与缩放均可用键盘操作。
- **三级瀑布式目录**：章 → 小节 → 三级小节逐级折叠，当前章默认展开，点带子节的父节开合其三级抽屉；章按钮与带子节的父节在右侧显示子菜单数量徽标（数字与抽屉里实际挂载的小节数一致）；工具条最左的「目录」按钮收起/展开目录，窄屏下目录为浮层抽屉，选中叶级小节后自动收起。
- **阅读偏好**：顶部工具条显示当前章节滚动进度，支持调整正文 15–21px 字号、切换浅/深色主题与整页全屏阅读（按 Esc 或再点按钮退出）。字号与手动主题选择跨刷新保存；首次访问跟随系统主题偏好；不支持全屏 API 的浏览器会隐藏该按钮。

## 架构

### 模块与加载顺序

页面按依赖顺序加载四个脚本，顺序不可调换：

```html
<script src="lessons.js"></script>     <!-- 课程数据 → window.CHAPTERS / window.CHAPTER1 -->
<script src="code-blocks.js"></script> <!-- 判定规则 → window.KRC_CODE_BLOCKS -->
<script src="highlight.js"></script>   <!-- C 语法高亮 → window.KRC_HIGHLIGHT -->
<script src="app.js"></script>         <!-- 渲染与全部交互 -->
```

初始化链路：

1. `<head>` 内的内联脚本在首屏绘制前恢复明暗主题、正文大小和目录收缩状态，避免闪烁。
2. `lessons.js` 拉取 `course-content.json`，**快速失败**式校验：章数必须为 12（1 前言 + 8 章 + 3 个附录），每章需有 `meta`/`tutorials`，`meta.kind` 若存在只能是 `"preface"` 或 `"appendix"`，教程字段与段落数下限必须满足（前言与附录是只读书稿正文，只需正文有内容）。最后设定 `window.CHAPTERS` / `window.CHAPTER1`（首章 = 前言与序）并广播 `course-content-ready`；失败则设 `window.COURSE_CONTENT_ERROR` 并广播 `course-content-error`。
3. `code-blocks.js` 以 UMD 包装导出 `isRunnableProgram(code)`（Node 下 `require` 可拿到同一份实现）。
4. `highlight.js` 以 UMD 包装导出 `highlight(code)`：编辑器高亮层与正文代码框（`pre.card-code`）共用这一份着色规则，`tools/test_highlight.js` 同样 `require` 它做回归。
5. `app.js` 监听就绪事件后执行 `init()`：同步目录状态并绑定工作台/编辑器 → 渲染上次阅读章节 → 绑定阅读控件并更新进度 → 拉取编译器列表。

### 渲染

每章的渲染顺序（都在 [`app.js`](../app.js) 的「渲染教程」区段内）：

| 函数 | 产出 |
| --- | --- |
| `renderChapterNav()` | 左栏三级瀑布式目录：每章一个 `.chapter-item`（章节按钮 + 内嵌小节抽屉）；编号栏前言显示 `0`、正文章显示 `1…8`（不补零）、附录显示 `A`/`B`/`C`；有子菜单（二级小节）时在按钮右侧显示数量徽标 `.chapter-tab-count`（无子节不输出） |
| `renderChips()` | 当前章抽屉内的小节 chips（目录的第二、三级）：两段编号的二级小节直挂，三段编号的三级小节收进父节 `.chip-group` 抽屉（点父节开合；手风琴语义，同一时刻至多只展开一个三级抽屉）；带子节的父 chip 显示数量徽标 `.chip-count`（统计编号前缀匹配的三级小节数，与抽屉挂载规则同源） |
| `renderSections()` | 正文：按 PDF 顺序输出小节（`0.1`、`1.5`、附录的 `A.1` → `h2`，`1.5.1`、`A.2.1` → `h3`） |
| `decorateRunnableCode()` | 给正文中命中判定的代码块追加「载入编辑器 / ▶ 运行」按钮 |
| `highlightCodeBlocks()` | 给 `#sections` 内全部 `pre.card-code` 着色：取 `textContent` 回填 `innerHTML`（与「复制 / 载入编辑器」同源，幂等），须在 `addCopyButtons` 之前执行 |
| `addCopyButtons()` | 给 `#sections` 内全部 `pre.card-code` 包 `.code-fig` 容器并加右上角「复制」按钮（复制 `pre.textContent`，须在 `decorateRunnableCode` 之后执行） |
| `setupSpy()` | 滚动高亮：`IntersectionObserver` 触发后按几何选出「顶边已越过视口 25% 横线的最后一个小节」高亮；当前项为三级小节时自动展开其父组，为叶级二级小节时收起全部三级抽屉（始终维持同一时刻至多一个抽屉打开） |
| `selectChip()` | 点击 chip 时立即高亮并「锁定」（用户真实滚动 wheel/触摸/按键后才交还滚动侦测），避免平滑跳转途中高亮被上一长节抢占而错位；同时收起非本级的三级抽屉（本级分组保持原开合，叶级二级小节收起全部） |

DOM 元素之间靠 `data-*` 属性约定通信，新增元素时请沿用同一命名：

| 属性 | 用途 |
| --- | --- |
| `data-chapter` | 目录中的章节序号 |
| `data-outline-topic` | 滚动高亮定位（小节编号） |

### 阅读工具条

顶部 `.reading-dock` 是粘性工具条，最左是目录开合按钮，其后依次是章节进度与阅读偏好；正文列 `.lesson` 不设最大宽度（宽度由 `.layout` 的边距与目录列决定）。

| 功能 | 实现 |
| --- | --- |
| 目录开合 | `setupTocToggle()` 切换 `<html>` 的 `toc-collapsed` 类：工具条最左的 `#tocToggle` 是常驻入口（窄屏下浮层抽屉会盖住工具条，故抽屉内另有 `#tocClose`）；单个按钮兼顾开合，文案与图标随状态改成下一步动作 |
| 章节进度 | `updateReadingProgress()` 按当前 `#sections` 的滚动范围算百分比，`scroll` / `resize` 经 `requestAnimationFrame` 合并重算；切换章节后归零 |
| 字号 | `applyReadingFontSize()` 写 `--reading-font-size`（15–21px），到达上下限时禁用对应按钮 |
| 主题 | `applyReadingTheme()` 切换 `<html>` 的 `data-theme`；首屏由 `index.html` 内联脚本按存档或系统偏好预置，避免闪烁 |
| 全屏 | `setupFullscreenToggle()` 让整页 `documentElement` 进入全屏（兼容 `webkit*` 前缀），监听 `fullscreenchange` 回写按钮文案与 `aria-*`；浏览器不支持时隐藏按钮 |

### 编辑器与工作台

编辑器是「高亮层 + 透明 `textarea`」的叠加结构：`#hl` 渲染着色后的代码（不可交互），`#code` 负责输入与光标，行号列 `#gutter` 与之同高；三者都绝对定位、自身不产生滚动条，因此 `syncScroll()` 必须把 `textarea` 的滚动位置同步给高亮层与行号列，否则文字与光标会错位。

`highlight()`（实现在 [`highlight.js`](../highlight.js)）用单趟正则按「注释 → 字符串/字符 → 预处理行 → 数字 → 标识符」的优先级交替匹配，每段先转义再包 `span`，因此注释与字面量内部的词不会被后续分组重复着色。字面量一律不跨行：未闭合的 `"` 只染到行尾，字符字面量必须同行闭合（避免正文里的英文撇号被误染）。返回值不带尾换行——正文代码框回填后与原文行数一致；编辑器由 `renderEditor()` 补一个换行对齐行号列。

工作台是 `position: fixed` 的浮层，拖动标题栏与右下角缩放手柄都使用 pointer capture，指针移出窗口也不会丢失拖动；尺寸与位置始终被夹在视口内（留 12px 边距）；无鼠标时可用方向键（Shift 加速）。页面加载后默认隐藏（`index.html` 静态声明 `hidden`，顶部工具条的「打开代码工作台」按钮可见），由 `showWorkbench()` / `hideWorkbench()` 切换显隐：正文代码块的「载入 / 运行」会自动弹出，初始化时载入起始代码后也会重新收起。

### 在线编译

- 编译器列表来自 `https://wandbox.org/api/list.json`，取 `language === "C"` 的条目；取不到时退化为仅含 `gcc-13.2.0-c` 的占位配置（下拉框会标注「占位配置」）。
- 运行把编辑器内容、`stdin`、编译器名与标准选项提交到 `https://wandbox.org/api/compile.json`；请求期间 `state.running` 为真，运行按钮禁用，避免并发提交。
- Wandbox 的 `status` 非 `"0"` 并不等于编译失败，判错以编译器消息为准。

## 课程数据格式

`course-content.json` 是长度为 12 的数组：第 1 个元素是前言章节（`meta.kind = "preface"`），中间 8 个是正文章，最后 3 个是附录（`meta.kind = "appendix"`）。

12 章全部由管线从 `md/*.md` 全量重建，形如：

```jsonc
{
  "meta": {
    "chapter": "第1章 导言"
  },
  "tutorials": [
    {
      "number": "1.5.1",          // 小节编号，章内与全课程唯一
      "title": "文件复制",

      "paragraphs": ["<p>…</p>"]  // 该节标题下的全部块（块级 HTML）
    }
  ]
}
```

要点：

- **`tutorials`（188 个：6 前言 + 91 正文 + 91 附录）是逐节正文**，`number`、`title`、`paragraphs` 全部由管线从 md 重建。
- **`meta.kind` 由小节编号前缀推导**：字母前缀 → `"appendix"`、`0.` 前缀 → `"preface"`、正文章不带该字段，形如：

  ```jsonc
  {
    "meta": {
      "chapter": "附录A 参考手册",
      "kind": "appendix"          // 前言同理为 "preface"；正文章不带该字段
    },

    "tutorials": [
      {
        "number": "A.2.1",
        "title": "记号",
        "paragraphs": ["<p>…</p>", "<pre class=\"card-code\">…</pre>"]
      }
    ]
  }
  ```

  附录 C 的书稿没有 `##` 标题，整篇被合成为一个小节 `C.1`。
- `paragraphs` 是块级 HTML 字符串数组，段落顺序严格保持书稿中的出现顺序。

## 数据管线

书稿由教材 PDF 生成，但 **`md/` 经人工整理，是课程数据的唯一来源**（已纳入版本控制）：

```powershell
python tools/pdf_to_md.py            # 第 1 步：PDF → md/*.md（仅当 md/ 尚无书稿时执行）
python tools/pdf_to_md.py --force    # 第 1 步强制重跑：整体覆盖 md/ 并清理未再生成的旧图片
python tools/md_to_course.py         # 第 2 步：md/*.md → course-content.json（并复制插图到 images/）
python tools/md_to_course.py --verify  # 只做一致性校验，不改写 JSON、不复制图片
```

日常修改教程**只跑第 2 步**即可。第 1 步默认拒绝覆盖已有 `md/`：脚本原始输出与人工整理后的书稿并不相同（句读、图题注、三级小节标题、图片命名都有差异），重跑会丢失这些整理结果，必须显式加 `--force`。两个脚本都按自身位置（`tools/`）回退一级定位输入输出，因此可在任意目录调用（通常在仓库根目录执行）。

### `tools/pdf_to_md.py`

用 `pypdf` 读取文字坐标与字体信息，先按 y 聚行重建页面视觉行，再依据 PDF 内嵌书签把全书切成「前言与序 / 各章 / 附录 / 索引」等输出单元，逐单元渲染为 Markdown：Courier 字体占比高者判为代码行（按行首 x 换算成等宽空格缩进）、跨页的裸页码按 y 坐标剔除、插图按内容 SHA-1 去重后落盘为 `md/images/`。原书内置的多栏「目录」页无法按行重建，整页跳过，改由 `write_readme()` 依据书签生成等效目录 `md/README.md`。

输出是确定的：同一 PDF 每次运行得到逐字节相同的结果（不依赖时间戳或随机数）。每次运行会删除 `md/images/` 中本次未再生成的旧图片。

### `tools/md_to_course.py`

按文件名顺序读取 `md/*.md`（不区分前言、正文与附录），依书稿自带的 `## ` / `### ` 标题切分小节，把块级内容转成 HTML，然后：

- 每节的 `paragraphs` ← 该节标题下的全部块；
- 首节的块包含章首导言，因此导言也随之进入本章首节；
- 三级小节只取自身标题下的正文，父节不再吞并三级小节的内容；
- 同步复制书稿引用的图片到 `images/`。

行内标记支持 `` `code` ``、`**粗体**`，以及**行内上下标**：`^x^` → `<sup>x</sup>`、`~x~` → `<sub>x</sub>`（如 `10^38^` → `10<sup>38</sup>`、`H~2~O` → `H<sub>2</sub>O`）。分隔符之间的内容须是至多 12 个不含空白的字母/数字/运算符字符且至少含一个字母或数字，`` `code` `` 内不转换——因此 C 里的按位取反 `~077`、异或 `x ^ y`、字符 `'~'` 等写法不会被误转。围栏代码块整体不做任何行内转换。

`md/` 是唯一事实来源：不维护书稿名单，也不读取既有 `course-content.json`，每次运行都按文件名顺序把 `md/*.md` 全量重新生成一遍——小节编号、标题、`meta.chapter` 与章节顺序一并由 md 重新推导，不排序、不去重。

**统一的 md 格式（所有书稿一视同仁）**：`# ` 是章标题，取作 `meta.chapter`（缺 h1 时回退用文件名）；`## x.y 标题` / `### x.y.z 标题` 是带编号小节，编号也可带附录字母前缀（`A.1` / `A.2.1`）；`## 标题` / `### 标题` 是无编号小节，编号按本章编号前缀顺序合成——前言书稿的各篇序言 `## ` 标题因此得到 `0.1`、`0.2`…。章编号前缀的推导顺序是：首个带编号小节的前缀 → h1 里「附录X」的字母 → 文件名开头的数字（`00-前言与序.md` → `0`）；整篇没有任何 `##` 标题时（如附录 C）章首导言合成为 `<前缀>.1` 一小节。`meta.kind` 由小节编号前缀决定：字母前缀 → `"appendix"`、`0.` 前缀 → `"preface"`、其余正文章不带该字段。

写盘后立即做**双向校验**：每节 md 纯文本 ⇔ JSON 去标签文本逐节相等（12 章同一套比对）、图片数量一致；不一致则打印首个差异位置并以退出码 1 结束。`--verify` 只做这一步校验（不写 JSON、不复制图片），适合提交前检查。

## 开发约定

- **无构建、无第三方运行时依赖**：浏览器端统一使用 ES5 写法（`var` + 字符串拼接），不引入打包器或 CDN 库；改完直接刷新页面。
- **注释与文案使用简体中文**，代码注释只写需要澄清的地方。
- **数据与页面解耦**：增改教程内容只动 `course-content.json`（或 `md/` + 管线），不碰页面代码。
- **单一事实来源**：正文代码块的可编译判定只在 [`code-blocks.js`](../code-blocks.js)、C 语法高亮只在 [`highlight.js`](../highlight.js) 里实现一次，页面与 Node 测试共用。
- **样式走变量**：颜色、圆角、字体一律经 CSS 变量；半透明色用 `color-mix` 从主题色派生，新增一种颜色通常只需在 `style.css` 的 `:root` 块加一行。
- **可访问性**：工作台的拖动/缩放/关闭都有键盘替代操作，动态区域带 `aria-*` 标注。

## 测试

回归测试全部是纯本地的 Node 脚本，不访问网络，在仓库根目录执行：

```powershell
node tools/test_course_data.js     # 课程数据：12 章 / 188 节、编号唯一、正文篇幅下限
node tools/test_code_blocks.js     # 「可在线编译」判定（与 code-blocks.js 同源）
node tools/test_highlight.js       # C 语法高亮往返与 token 分类（与 highlight.js 同源）
node tools/test_toc_accordion.js   # 侧栏三级抽屉的手风琴开合与选中收口
node tools/test_toc_counts.js      # 侧栏目录的子菜单数量徽标（与各自抽屉挂载一致）
```

后两个脚本不复制页面逻辑：被测函数（`setGroupOpen` / `closeGroupsExcept` / `selectChip` / `highlight`、`renderChapterNav` / `renderChips` 等）从 `app.js` 源码按名字截取本体，注入一个最小假 DOM 执行，因此覆盖的是页面真实实现；数字期望值在测试里按同一套编号规则独立算出（编号两段 = 直挂抽屉的二级小节，前缀匹配 = 父节的三级小节）。改动目录交互时顺手补一条断言，提交前把五个脚本都跑一遍。
